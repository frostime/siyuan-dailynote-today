# 日记文档优先视图变更规格

## 问题陈述

Daily Note View 当前以“日期 × 笔记本”的候选位置为主组织内容。用户在回顾过去日记时，会看到大量未创建日记的空栏；同一天已经存在的日记与没有日记的笔记本被同等对待，内容密度低，也难以看清实际写过什么。

现有视图还存在以下体验问题：

- 未来日期不可正常浏览和手动创建日记。
- 点击创建后，刚创建的日记不能可靠地在当前视图立即显示。
- 内容、日历、笔记本和日期导航的职责混杂，控制项占用内容空间或脱离当前内容上下文。
- 同一笔记本的不同日期日记不能方便地横向顺序阅读。
- 日历视图的常驻日详情会遮挡日历本身，妨碍按日期扫描已有日记。

## 目标与非目标

### 目标

1. 将内容视图的展示单位改为**实际存在的日记文档**，而不是可能存在的空位置。
2. 保留同一天多个笔记本均可有日记的模型；它们应作为多篇日记文档呈现。
3. 允许用户手动创建未来日期的日记，但浏览日期绝不自动创建文档。
4. 支持在同一笔记本内，按日期顺序横向阅读多篇已有日记。
5. 保留并统一单篇、分栏、卡片三种日记文档布局。
6. 让高频视图切换保持直接可见，让仅在特定状态下才有意义的参数成为不占内容流的次级控件。
7. 提供周、月、年三种日历粒度；日历专注于发现和跳转，不常驻遮挡内容。

### 非目标

- 不改变 Daily Note 的身份规则、存储路径模板、重复日记处理策略或预约功能。
- 不在本变更中新增日记内容编辑能力；嵌入式文档仍使用现有编辑能力。
- 不承诺机械复刻 UI 原型中的尺寸、配色、具体控件形状或演示数据。
- 不为不存在的日记合成占位栏、空日历标签或虚构文档。

## 方案

采用“**笔记本负责导航，日记文档负责呈现**”的模型：

- 笔记本用于筛选浏览范围、选择连续日期的目标笔记本，以及指定创建目标。
- 日记文档是内容区、日历标签和布局切换的唯一展示单位。
- 一个没有匹配日记的笔记本仍可从 Notebook Menu 选择，但不会在内容区留下空列；应展示清晰的创建引导。
- 内容视图有两种分组方式：同日和连续日期。布局切换只改变同一批日记文档如何显示，不改变分组语义。
- 日历是查找已有日记的入口。日期单元进入该日期的内容视图；日记标签直接进入对应文档。日历不使用常驻详情面板。

该方案把“用户正在读哪些真实文档”和“用户用什么范围找到它们”分开，避免空笔记本消耗文档阅读空间。

## 原型的使用边界

同目录的 `daily-note-document-first.html` 仅用于传达本规格中的 UI 逻辑、信息层级和大致交互感受。

实现时必须以实际 SiYuan API、现有组件行为、可用空间、性能和无障碍要求为准，不能将该 HTML 的 DOM 结构、样式尺寸、演示数据或控件排列无条件照搬到插件中。若实现现实使本规格的行为边界或用户可见交互产生不明确的取舍，必须先向用户请求决策，而不是自行以原型为依据补全需求。

## 行为契约

### 内容与笔记本

- 内容视图默认只显示查询到的日记文档。
- 同日分组：显示选定日期、选定笔记本范围内的所有日记文档。选择“全部笔记本”时，同日不同笔记本的已有日记同时可见。
- 连续日期分组：只适用于一个明确的笔记本。按日期排序后显示该笔记本的已有日记，日期导航按已有日记的顺序前后移动，不经过不存在的日记。
- 当用户在连续日期分组选择“全部笔记本”时，界面不猜测目标笔记本，也不生成空列；应要求用户从 Notebook Menu 选择一个笔记本。
- Notebook Menu 是笔记本选择入口。它不应永久挤占内容宽度。

### 布局

同一分组下的日记文档可使用以下布局：

| 布局 | 用户可见行为 |
|---|---|
| 单篇 | 显示当前选中的一篇日记；同一结果集中的其他日记可在日期标题同行切换。 |
| 分栏 | 并排显示当前结果集中的多篇日记。 |
| 卡片 | 以可识别标题、笔记本和日期信息的卡片概览当前结果集；卡片可进入对应日记。 |

- 同日分栏时，用户可选择分栏数量。可见数量的具体选项、默认值和溢出策略必须在实现前根据可用空间确认。
- 连续日期分组时，用户可选择一次显示的日期数量；横向排列的每一列必须属于同一个笔记本且按日期顺序排列。
- 分栏数量、连续日期数量等仅在相关状态下出现，且不能为它们额外预留主内容区高度。

### 日期与创建

- 用户可以导航到过去、今天和未来日期。
- 未来日期与过去日期均不会因为查看而自动创建日记。
- “创建 Daily Note”允许选择日期和笔记本，并允许选择未来日期。
- 创建成功后，当前视图必须直接使用创建结果显示新日记；不得仅依赖可能尚未完成索引更新的重新查询。
- 如果当前分组或筛选范围不包含新建日记，视图应切换到能显示该文档的上下文。

### 控件层级

以下高频主状态切换必须直接可见，不应收进默认折叠菜单：

- 内容 / 日历视图
- Notebook Menu 按钮
- 日期前后导航
- 内容视图中的同日 / 连续日期分组
- 内容视图中的单篇 / 分栏 / 卡片布局
- 创建日记动作

次级控件使用始终为按钮形态的右下角悬浮入口；入口及展开内容必须使用绝对定位或等价机制，不参与内容区的纵向布局。

次级控件随当前状态变化：

| 当前状态 | 次级控件 |
|---|---|
| 同日 + 分栏 | 分栏数量 |
| 连续日期 | 一次显示的日期数量 |
| 日历 | 周 / 月 / 年粒度 |
| 其他内容状态 | 无额外参数时显示空状态或不显示菜单项 |

### 日历

- 日历支持周、月、年粒度。
- 日历中的日记标签只代表实际存在的日记文档，并能显示同一天多个笔记本的多个日记。
- 点击日期单元的空白区域，进入该日期的同日内容视图；无日记的日期在内容视图中提供创建引导。
- 点击日历中的日记标签，进入对应日记。
- 年视图应在不渲染完整文档内容的前提下标示包含日记的日期；点击日期进入对应月份或内容上下文。
- 不显示常驻的日详情面板、固定侧栏或遮挡日历的浮层。

## 实现决策

- 日记文档的查询结果是展示状态的权威来源；笔记本列表不是待渲染栏位的列表。
- 创建操作返回的文档是本地即时显示的权威来源，后续查询用于同步校正，而不是阻塞首次渲染。
- 分组决定结果集，布局决定结果集的呈现方式。这两个状态必须独立，避免“分栏”隐含改变笔记本或日期范围。
- 主状态控件和次级参数控件必须分层：前者面向频繁浏览，后者只在特定模式中出现。
- 日历和内容视图共享日期、笔记本和已存在日记的事实，但各自服务不同任务：日历负责发现，内容视图负责阅读和创建。
- 对重复日记，必须沿用插件既有的重复日记呈现和处理行为；本变更不得悄悄选择或删除其中任一文档。

## 未决事项

以下事项会影响具体实现或体验，实施前需要结合现有 API 和用户确认：

1. 同日分栏与连续日期分别可选的数量范围、默认值，以及窗口过窄时采用横向滚动还是降级布局。
2. 年视图在日记数量很多、同一天有多个笔记本时的标记密度与详情入口。
3. 创建后若用户当前位于周/月/年日历中，是否切换到内容视图，或仅更新日历并保留当前粒度。
4. 历史日记缺少日记属性时，在新视图中应如何呈现；必须与现有兼容性修复功能保持一致。
5. 现有 SiYuan 查询接口对大范围周/月/年查询的性能边界和分页策略。

## 验收标准

### 自动或可重复检查

- 项目构建成功，类型检查和现有自动化检查通过。
- 在至少两个笔记本、同一天各有一篇日记的场景中，同日视图只展示两篇实际文档，不渲染其他笔记本的空栏。
- 在一个笔记本有多个不同日期日记的场景中，连续日期分组按日期顺序展示已有文档；前后导航跳到相邻已有日记。
- 创建未来日期日记后，创建结果无需关闭或刷新自定义页签即可显示。
- 日历周、月、年视图只标示已有日记；日历页面不存在常驻日详情面板。
- 主控栏与右下角次级控件同时存在时，次级控件不增加内容区的布局高度。

### 用户验证

- 用户能够一眼区分“笔记本用于导航”和“日记文档用于阅读”，且不再觉得笔记本轴把空白与内容同等平铺。
- 用户能在不寻找折叠菜单的情况下完成内容/日历切换、日期切换、笔记本切换、同日/连续日期切换和布局切换。
- 用户确认单篇模式的日记切换标签位于日期标题同行，而非文档下方或视图底部。
- 用户确认日历在没有常驻详情面板时更适合扫描日期分布。

## 术语表

**Daily Note / 日记文档**：某个笔记本、某个日期下实际存在的一篇日记文档；是内容区和日历标签的展示对象。

**笔记本 / Notebook**：SiYuan 中容纳文档的笔记本。在本变更中，它用于导航、筛选和选择创建目标，不等同于内容区的一列。

**同日分组**：以一个日期为范围，显示该日期下、所选笔记本范围内全部实际存在的日记文档。

**连续日期分组**：以一个明确笔记本为范围，按日期顺序展示多篇已有日记文档的分组方式。

**布局**：对同一结果集的显示方式，包括单篇、分栏和卡片；布局不改变结果集的日期或笔记本范围。

**主状态控件**：用户频繁切换、直接决定当前浏览上下文的可见控件。

**次级控件**：仅在特定主状态下出现的参数控件，通过右下角的悬浮按钮按需展开，且不占据内容流空间。

**Notebook Menu**：由顶部笔记本按钮展开的笔记本选择菜单。
